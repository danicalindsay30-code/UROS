## Dual-Polarisation RRC Matched Filter 
SystemVerilog implementation of the reciver matched filter for a dual-polarisation QPSK coherent optical DSP chain, verified against 
the golden python model.

## 1. Function

The matched filter is the receiver half of a root-raised-cosine (RRC)
pulse-shaping pair. The transmitter shapes each symbol with an RRC
impulse response; the receiver applies the same response again. The
cascade of the two forms a full raised-cosine response, which is
zero at every symbol instant except its own, so inter-symbol
interference vanishes at the sampling points. Applying the matched
filter also maximises signal-to-noise ratio at the decision instant
for additive white Gaussian noise.

The signal is dual polarisation and complex, giving four real streams:

| Stream | Meaning |
|---|---|
| `Ix` | X polarisation, in-phase |
| `Qx` | X polarisation, quadrature |
| `Iy` | Y polarisation, in-phase |
| `Qy` | Y polarisation, quadrature |

Each stream is filtered independently by an identical real FIR, so the
top level instantiates four copies of the same module.

## 2. Architecture

```
          Ix ──► matched_filter ──► Ix_out
          Qx ──► matched_filter ──► Qx_out
          Iy ──► matched_filter ──► Iy_out
          Qy ──► matched_filter ──► Qy_out
                dp_matched_filter
```

Inside each `matched_filter`:

```
sample_in ──► [ 17-stage shift register ]
                     │
                     ├─► × tap[0] ─┐
                     ├─► × tap[1] ─┤
                     ├─►   ...     ├─► accumulate ──► round ──► >>7 ──► sample_out
                     └─► × tap[16] ┘
```

- **Shift register** — 17 stages of 8-bit signed, one new sample per
  clock, giving the delayed samples the FIR needs.
- **Multipliers** — 17 signed 8×8 products.
- **Accumulator** — sums all 17 products.
- **Rescale** — the coefficients were scaled by 128, so the sum is
  shifted right by 7 to restore the input's scale. A half-LSB is added
  before the shift so the result rounds to nearest rather than
  truncating (see section 3.4).

Coefficients are held in `rrc_coefficients.vh`, generated by the same
Python function that produces the golden model's filter, so the model
and the RTL cannot drift apart.

## 3. Fixed-point analysis

### 3.1 Input format

The channel output is scaled so its largest magnitude maps to full
scale of a signed 8-bit word, modelling an 8-bit ADC:

```
input_scale = 127 / max|E_noise|
x_int = round(E_noise · input_scale)      range −128 … +127
```

The same `input_scale` is applied to the reference output. This is
important: an earlier version of the pipeline scaled the input and the
reference by two independently computed factors, which produced a
constant ≈1.36× offset that looked like a hardware gain error. One
scale factor, applied consistently through the chain.

### 3.2 Coefficient format

The RRC impulse response (span 8, 2 samples/symbol, roll-off 0.35,
unit energy) gives 17 taps. Scaling by 128 and rounding to signed 8-bit
gives:

```
[0, 1, −2, 2, 5, −12, −8, 55, 99, 55, −8, −12, 5, 2, −2, 1, 0]
```

| Property | Value |
|---|---|
| Format | Q1.7, signed 8-bit |
| Peak tap | 99 of 127 — good use of the available range |
| Max coefficient error | 0.0026 |
| Taps are symmetric | yes |

The symmetry is not yet exploited. See section 6.

### 3.3 Accumulator width

Bit growth in an FIR is set by the sum of the coefficient magnitudes,
not by the number of taps:

```
Σ|taps| = 269
worst-case accumulator = 127 × 269 = 34,163
bits required = ceil(log2(34163)) + 1 (sign) = 17 bits
```

The implementation uses 24 bits, so there are 7 bits of unused
headroom. This is safe but larger than necessary; the width was chosen
before the bound was derived.

### 3.4 Output format and rounding

After the shift by 7, the largest possible output magnitude is
34,163 / 128 ≈ 267, requiring 10 bits signed. The implementation uses
18 bits.

The shift must round to nearest:

```
sample_out = (accumulator + 64) >>> 7
```

A plain arithmetic shift rounds toward negative infinity. Measured
across 116 samples × 4 channels, truncation produced a mean error of
**−0.51 LSB** — a systematic bias on every sample, invisible to a
visual comparison and obvious the moment the mean is taken. Adding
the half-LSB before the shift removed it.

| | Truncation | Round to nearest |
|---|---|---|
| Exact match vs model | 50.43 % | **70.47 %** |
| Mean error | −0.51 LSB | **+0.015 LSB** |
| Max \|error\| | 2 LSB | **1 LSB** |

## 4. Verification method

Three models are used, each answering a different question.

| Level | Model | Question | Criterion |
|---|---|---|---|
| 1 | Floating-point pipeline | Does the DSP algorithm work? | BER vs OSNR |
| 2 | Bit-exact integer model | What does quantisation cost? | measured, reported |
| 3 | RTL | Is the implementation correct? | **0 mismatches vs level 2** |

The RTL is deliberately **not** compared against the floating-point
model as a pass/fail test. Those two compute different things: the
float model filters float samples with float coefficients, the RTL
filters quantised samples with quantised coefficients. They differ by
input quantisation, coefficient quantisation, and output rounding.
Comparing them gives a ±1 LSB spread that is a measurement, not a
tolerance.

## 5. Results

Behavioural simulation, 116 samples × 4 channels, seed 42, OSNR 20 dB,
DGD 0.1.

### RTL vs Python floating-point model

| Metric | Value |
|---|---|
| Exact match | 70.47 % |
| Within ±1 LSB | **100.00 %** |
| Max \|error\| | 1 LSB |
| Mean error | +0.015 LSB (unbiased) |
| RMS error | 0.543 LSB |

Per channel, the exact-match rate is 73.3 / 69.0 / 74.1 / 65.5 % for
Ix / Qx / Iy / Qy, with all four means within ±0.09 LSB of zero. No
channel behaves differently from the others.

The RMS error of 0.543 LSB is consistent with the combined
quantisation noise of the input and coefficient quantisers, each
contributing on the order of 1/√12 ≈ 0.289 LSB. The residual error is
explained by quantisation theory rather than by an implementation
fault.

## 6. Known limitations

- `input_scale` is computed from the dataset rather than fixed as a
  design constant, so the format changes between runs and results
  across seeds are not directly comparable. A real receiver has a
  fixed ADC format with an AGC ahead of it.
- The accumulator is 24 bits where 17 is provably sufficient, and the
  output is 18 bits where 10 is sufficient. Neither is a fault, but
  neither is justified by the analysis either.
- The filter output is currently combinational from the shift
  register. This simulates correctly but will limit the achievable
  clock frequency; the adder tree needs pipelining before
  implementation.
- There is no reset. The shift register is cleared by an `initial`
  block, which works in simulation but leaves no way to restart the
  filter in hardware.
- Coefficient symmetry is not exploited. The taps are symmetric and
  the outer two are zero, so a pre-adder structure would need roughly
  half the multipliers. Not yet implemented or measured.
- Only one dataset (seed 42, OSNR 20 dB) has been used. A sweep across
  seeds, OSNR values and DGD values has not yet been run.

### Reproducing the simulation

1. Generate the stimulus and reference by running the pipeline script,
   which writes both files into `03_Data/`.
2. Create a Vivado project, add the three RTL sources and the
   testbench, and set the include path to the directory holding
   `rrc_coefficients.vh`.
3. Run behavioural simulation with `run -all`. The default 1000 ns run
   length stops after 50 of the 116 samples and leaves the output file
   empty.
4. Compare `MF_sv_filter_output.txt` against `MF_python_model_out.txt`.
